# Threat model and enforcement boundaries

## Trust zones

1. **Production collector** (proposed): read-only Langfuse project access, approved Looker Looks and bounded log exports. No code push, deployment or ad mutation authority.
2. **Sanitized evidence store** (proposed): tenant-scoped snapshots, retention policy, access audit and immutable provenance.
3. **Implementation worker** (proposed): only approved code and redacted evidence; isolated network/filesystem; no production credentials, hidden evaluation labels or publisher token.
4. **Trusted evaluator**: owns acceptance expectations outside the candidate. The sample regenerates exact predefined repairs and rejects altered candidates before treating them as verified. This is an integrity check, not a general arbitrary-patch evaluator.
5. **Publisher**: optional explicit execution, draft PR only. Human review, protected CI and release authorization are separate controls.

## Threats and responses

| Threat | Sample behavior | Additional production requirement |
|---|---|---|
| Prompt injection in a conversation/log | No LLM or dynamic command execution from evidence; allowlisted fields and signals | Treat every trace/document/tool result as untrusted; enforce tool capabilities outside model |
| Cross-tenant or wrong-release attribution | Exact identity and window matching in synthetic evidence; mismatch means no repair | Enforce tenant authorization before retrieval; do not rely on caller-supplied tenant metadata |
| False root cause from a quality drop | Requires correlated fixture events and failing baseline; timeout escalates | Evaluate cohort shifts, evaluator drift, missing labels and alternative causes |
| Secrets in reports/PRs | Raw input/output/messages discarded; publisher generates its body from validated fields | Approved redaction service, DLP, restricted artifact storage and keyed pseudonyms |
| Identifier leaks | Synthetic core identifiers are hashed | Plain hashes do not anonymize low-entropy IDs; use governed keyed pseudonyms |
| Malicious endpoint or redirect | HTTPS and explicit approved hostname; no ambient proxy; redirects rejected | Egress firewall, DNS/IP policy, private endpoint governance and credential scoping |
| Resource exhaustion | HTTP timeout/size bounds; log size/line bounds; evaluator timeout | CPU/RAM/disk/output quotas, per-incident budgets and bounded durable retries |
| Evaluator gaming | Candidate inventory and exact regenerated bytes compared; report tampering rejected | Separate protected evaluation repository/service, private holdouts and signed attestations |
| Arbitrary candidate execution | Supplied candidate is compared with trusted regenerated code for verification | OS/container/VM sandbox for arbitrary code; subprocess alone is not isolation |
| Publishing to the wrong repo/base | Explicit slug/origin check and fetched main/HEAD equality | Scoped GitHub App, protected environments, short-lived credentials |
| Duplicate remediation | Stable fingerprint; existing branch/PR causes a stop | Durable unique key, leases, compare-and-swap and safe recovery for distributed workers |
| Production campaign changes | No campaign mutation integration exists | Server-side authorization, payload-bound explicit consent, expiry and idempotency |
| Modified factory instructions/CI | No autonomous policy changes | Mandatory owner review for rules, evaluator, CI, baseline and permissions |

## Important limitations

The source checkout, bundled synthetic fixtures, evaluator and running Python process are trusted. The sample does not defend against a malicious local process concurrently editing files or the trusted controller itself. Content hashes are not signatures. The publisher checks copied bytes, but production needs immutable snapshots and attestations tied to the exact commit and artifact.

The HTTP host allowlist is operator configuration, not incident-provided input. It is not a DNS-rebinding defense. Allowed metadata fields can still leak a secret if an operator stores one in an ID; schema sanitization is not semantic DLP. Raw Langfuse fetch results must never be sent directly to PRs or models.

The evaluator captures subprocess output and has a deadline, but lacks a dedicated OS memory/output quota. Only the trusted sample code may be evaluated in this lab. A production worker must have no access to developer SSH keys, GitHub credentials, model credentials unrelated to its task, or production data.

## Release invariants

- A model cannot approve its own permissions or release.
- A score decline cannot authorize a code change by itself.
- A generated patch is not a passing evaluation.
- A static skill check is not behavioral safety evidence.
- A PR or merge is not proof of successful production remediation.
- Replaying a campaign-creation timeout must not create duplicate campaigns.
- Stop and escalate when evidence scope, provenance or completeness is uncertain.

## Review checklist

Confirm exact baseline and candidate identity; scoped evidence; raw-text exclusion; denied paths; baseline failure; candidate pass; no neighboring-agent regression; clear causal claim; unresolved alternatives; owner sign-off; rollout cohort; rollback artifact; and audit/retention handling.
